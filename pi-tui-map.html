Pi TUI anatomy

Pi interactive mode is a terminal screen composed from message history, an input editor, a footer, and optional extension surfaces. Extensions can render components, overlays, widgets, statuses, custom editors, and custom tool results.

Startup header

Appears when Pi starts. It reports shortcuts and discovered resources: context files, templates, skills, extensions.

Messages pane

The scrollback for user and assistant messages, tool execution rows, tool results, notifications, errors, and extension-rendered content.

Editor

Main input. It supports file references, path completion, multiline input, image paste, external editor, slash commands, and shell shortcuts.

Footer

Shows cwd, session name, token and cache usage, cost, context usage, model, plus extension status entries from setStatus.

Widgets

Extensions can pin lines above or below the editor. Common uses: plan mode, todo state, progress, and lightweight dashboards.

Custom UI

ctx.ui.custom() can show selectors, settings lists, loaders, games, question dialogs, or any component implementing render and input handling.

Overlays

Overlay components stack on top without clearing the screen. They support anchors, percentages, margins, size bounds, and responsive visibility.

Theming and keys

Themes provide color tokens for text, borders, messages, tools, markdown, diffs, syntax, thinking levels, and bash mode. Keybindings use namespaced ids like tui.editor.cursorUp.

How extension UI pieces plug in

ComponentEvery TUI piece implements render(width): string[], optional handleInput(data), and invalidate().
Built-insText, Box, Container, Spacer, Markdown, Image, SelectList, and SettingsList cover most needs.
InputComponents receive raw key data. Use matchesKey() and Key.*. Focusable inputs can position the hardware cursor for IME.
Render safetyEach rendered line must fit the supplied width. Use truncateToWidth or wrapTextWithAnsi for ANSI-aware output.
LifecycleAfter state changes, invalidate caches and request render. Theme changes call invalidate() so cached ANSI colors must be rebuilt.
Editor replacement: setEditorComponent() swaps the main input editor for custom editing modes.
Status: setStatus() adds persistent footer/status text until cleared.
Working row: setWorkingMessage(), setWorkingVisible(), and setWorkingIndicator() affect the streaming indicator.
Footer: setFooter() replaces the default footer and can react to branch changes.
