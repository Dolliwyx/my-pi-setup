# Implementation playbook

1. Inspect the relevant code and affected callers and tests. Restate the user's intention in your own words.
2. Visualize the proposed change using the smallest useful view: a diff, pseudocode, call tree, component tree, diagram, or mockup. Show the context needed to understand the change and its consequences.
3. Briefly describe the approach and planned verification. Ask for explicit approval and wait before making implementation changes.
4. After approval, implement and verify the agreed approach. If the scope or approach changes materially, explain the change and obtain approval again.
5. Report what changed, what was checked, and any remaining limitations.
